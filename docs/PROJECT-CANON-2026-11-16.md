# Бирмингем: Цена власти — действующие правила разработки и структура игры

**Дата фиксации:** 16 ноября 2026. **Основной репозиторий:** `Ssyap4/Birmingham-Price-of-Power-Play`.

Этот документ предназначен для непрерывной передачи проекта между чатами, Codex и разработчиками. При сомнениях сначала сверять фактическое состояние GitHub, а не выдавать запланированное за выполненное. Все ограничения ниже подтверждены автором игры.

## 1. Главное меню — только ДВА основных сюжетных направления

**А. «Детективные дела»** — один общий раздел/карта с Делами №001, №002 и будущими №003, №004, №005. **Запрещено** создавать отдельные главные кнопки для каждого из Детективных дел. Новые дела добавляются внутрь общего раздела. В проекте исторический HTML-переход `#districtsCard` ведёт к карте районов; сохранять этот рабочий контракт.

**Б. «Работа для своих»** — принятое автором атмосферное название бывшего рабочего режима «Криминальные дела». Это самостоятельная линия из пяти нелинейных историй CR01–CR05, встроенная как **один** большой раздел, а не пять кнопок на главной. В проекте исторический HTML-переход `#criminalEntry` ведёт к карте заданий; сохранять контракт. На экранах, где это заголовок самого режима, использовать «Работа для своих», сохранив технические ID `criminal`/CR01–CR05 и ключи сохранений.

Другие главные пункты — «Испытания», «Достижения», «Досье персонажей», «Профиль» — остаются вспомогательными функциями, а не основными сюжетными направлениями. Сейчас интерфейс этих кнопок исторически неоднороден: планируется полноценная общая художественная переработка, а не бессистемное добавление новых блоков.

Название «Поручения ближнего круга» **не использовать как название режима**, чтобы не конкурировать с «Детективными делами»; выражение «приказы/задания» допустимо для отдельных историй внутри «Работа для своих».

## 2. Снаряжение и художественная атмосфера

Символы/эмодзи в инвентаре криминального режима являются временными и **не соответствуют финальному качеству**. Утверждена замена на миниатюрные предметные иллюстрации в едином стиле 1920-х: узнаваемый револьвер, патроны, бинт, фонарь, документы, деньги, инструменты и т. д. Текущий каталог в `src/criminal/content.js` содержит **28** реальных ID предметов.

**Установленная рабочая база:** 28 отдельных иллюстрированных SVG-файлов `assets/criminal/equipment/<itemId>.svg`, добавленных коммитом `e4301bc2024af1ff58f64538eee6563f96f2e5b9`. В дальнейшей рабочей волне их подключили к `src/criminal/app.js` (инвентарь, ресурсные изменения, перевязка), экспортёрам объединённой и автономной сборки и к адресным браузерным/Node-тестам. Это векторные *интерфейсные* иллюстрации, не отдельные кинематографические кадры.

Новые кинематографические сцены по действующему художественному протоколу: **ровно одна новая сцена/иллюстрация за одно сообщение пользователя**, потом самостоятельная проверка; не генерировать серию сюжетных сцен одной волной. Для небольших UI-иконок допустима отдельная системная векторная разработка без генерации новых сюжетных кадров. Кандидаты CR01 `ambush` и CR02 `rescue` пока **не установлены** в GitHub art manifest. 40 исходных утверждённых WebP криминального режима сохраняются.

## 3. Приоритет разработки и интеграции

1. Полировка интерфейса, снаряжения и атмосферы всех пяти историй CR01–CR05, с проверкой реального прохождения.
2. Затем полноценный единый художественный слой главного меню, карты и досье — **два** больших сюжетных входа.
3. Затем общая тестовая HTTPS-сборка трёх работающих режимов (детективные Дела №001 и №002 внутри одного направления + «Работа для своих»).
4. Только после самостоятельного технического QA и приёмки автора — обсуждение слияния в `main`.

**Слияние не значит слияние историй/движков/сохранений**: сохраняем разные кодовые и локальные пространства, а игрок видит целостную игру. Существующие ссылки теста Safari и ветку `preview/unified-campaign-safari` не перезаписывать преждевременно.

## 4. Защита прогресса и качество

- Не менять без разрешения Дело №001, Дело №002, движки, флаги, профили, ключи сохранений и ранние достижения. Нельзя молчаливо мигрировать `birmingham_criminal_v2_` в `birmingham_campaign_*`.
- За `дело × персонаж × концовка` уникальная награда выдаётся только один раз, повтор не должен повторять уведомление. Все результаты и награды криминальной кампании должны проверяться повторным проигрыванием истории, а не верой в отредактированный localStorage.
- Автопроверки — только необходимая матрица для текущих изменений, без запуска всех долгих сценариев на каждую мелочь. При изменении экспорта, снаряжения и меню важны Node/DOM/Chromium/WebKit и регрессии старых дел.
- В первую очередь вертикальный мобильный интерфейс iPhone/Telegram Mini App, затем desktop. HTML открывается напрямую и через HTTPS. EXE/Electron/Tauri отложены до полного завершения игры (если вообще понадобятся).
- Не отправлять пользователю новую ZIP/HTML после каждого малого изменения: только после заметной законченной волны и самостоятельной приёмки. При крупных обновлениях сообщать точный SHA, состояние CI и фактически проверенные функции.
- Не обещать длительную работу «в фоне» без реально настроенной автоматизации. Для внешнего доступа используем GitHub/Vercel, без замены живых бета-версий до QA.

## 5. Организация чатов — правило 10+1

**В каждом новом чате 10 рабочих ответов**, на **11-м** — только точный подробный промпт-передача следующему чату (HEAD, последняя внедрённая задача, ветка, CI, открытые вопросы, следующий шаг, запреты). Это счётчик общения, а НЕ этапы разработки или релиза. Чистые вопросы/ответы по интерфейсу, подключению и другой справке к 10 рабочим ответам не прибавлять. В новой беседе начинать с 1/10. В текущей беседе счётчик указан в ответах ассистента.
