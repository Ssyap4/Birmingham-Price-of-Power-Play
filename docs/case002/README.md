# Дело №002 — «Последний поезд из Бирмингема»
**Публичный GitHub · отдельная сценарно-техническая ветка · v3.0 (черновик).**
**Важно:** это сценарный и тестовый пакет, НЕ версия игры. Main, работающий iPhone preview и Дело №001 не изменялись.

## Что готово в рамках v2
1. [Сценарная библия](case002-story-bible-v1.md) — неподвижная правда, временная шкала, мотивы, шесть глав и семь нравственно неоднозначных развязок.
2. [Первая половина сценария: вступление и главы I–III](case002-screenplay-acts-1-3-v2.md) — сцены P01–C10, оригинальные реплики, атмосфера, независимые улики.
3. [Вторая половина: главы IV–VI и семь концовок](case002-screenplay-acts-4-6-and-endings-v2.md) — судьбы свидетелей, сделки, разоблачения, несколько вариантов эпилогов.
4. [15 личных сцен пяти героев](case002-hero-scenes-v2.md) — по три уникальных эпизода: Джек, Финн, Элеонора, Виктор, Сэмюэл.
5. [Карта 89 узлов](case002-beat-graph-v1.json) — ID сцен и структурные маршруты; переходы должны быть дополнены игровыми guard/effect.
6. [Контракт сюжетных состояний](case002-logic-contract-v1.md) и [условия улик/финалов](case002-contract-v1.json) — 25+ видов доказательств, независимые пары, запреты на недоказанные концовки.
7. [Канон №001 → №002 и сохранения](case002-canon-save-compat-v2.md) — явный выбор предыдущего исхода, запрет воскрешения, совместимость старых ключей и наград.
8. [Ранние кинематографические образцы сцен](case002-opening-scenes-v1.md) — исходные редакторские ориентиры, прежде всего для сравнения с развёрнутым v2.

## Технический этап v3 — уже реализован в отдельной ветке
- [Движок Case 002](../../src/case002/engine-v3.js): 89 узлов, 7 финалов с предикатами, 26 идентификаторов улик, отдельные статусы Ады/Томми/Мерсера, отдельные сценарные флаги, специальные действия пяти героев.
- [Общий текстовый сценарный пакет](../../src/case002/browser-data-v3.js): один автономный JS-бандл, автоматически составляемый из сценарных документов, графа и контракта. Работает без запросов к внешним серверам и без картинок.
- [Текстовый мобильный прототип](../../preview/case002-prototype/index.html): HTML/CSS/JS с выбором героя, диалогами, реальными действиями, видимым уведомлением об улике, вкладками улик/дедукции/свидетелей и автосохранением. Это **не финальная игровая верстка** и не художественная версия.
- Запись черновых попыток по герою: `birmingham_case002_draft_v3_<heroId>`. Черновой архив и черновые награды имеют **свои** ключи. Движок НЕ пишет в старые сохранения №001.
- При завершении сохранение исхода фиксируется раньше, чем запись в архив: при обрыве записи повторный запуск допишет незавершённый архив без второй награды. Повреждённый архив не перезаписывается молча.
- Канон №001 выбирается явно из уже завершённых записей и сохраняется как снимок одной попытки. Все шесть исходов прежнего дела получили минимальный текстовый отклик; сложное влияние пока не реализовано.
- Проблемные особые маршруты HV02/HV03/HS02/HS03 выправлены: никто не перескакивает через необходимые встречи, стрелочный пост и проверку безопасности.

### Что ещё НЕ готово
- Полная матричная проверка всех комбинаций флагов и ресурсов за пределами эталонных 35 маршрутов; более сложные коллизии по-прежнему возможны.
- Полный художественный UI в стиле утверждённого меню (все иллюстрации будут утверждаться отдельно), портреты, звук/озвучка, окончательная адаптация Telegram SDK.
- Интеграция №002 с живой картой районов и публичными профилями/серверным архивом.
- Финальная редактура вариативных диалогов, динамические действия противников, баланс драматических рисков.

## Контроль качества
Только отдельный GitHub Actions workflow [case002-story-qa.yml](../../.github/workflows/case002-story-qa.yml), без 202 сюжетных сценариев №001:
- `node tests/case002/validate-contract.js`: проверка независимых пар улик и правил 7 финалов.
- `node tests/case002/validate-beat-graph.js`: 89 ID, отсутствие битых переходов, 15 эксклюзивных сцен, обязательные промежуточные этапы.
- `node tests/case002/simulate-story-model-v2.js`: **35 не игрушечных «проверок из ниоткуда», а реально пройденных маршрутов по графу** с выбором действий и набором доказательств; дополнительно отсекает неearned исходы, дублирующийся лут, выбор чужого героя и необоснованный пропуск главы.
- `node tests/case002/validate-canon-v2.js`: **1050 проверок совместимости предыдущего героя, исхода №001, нового героя и финала №002**; сохранение уникальности старых и новых наград.
Это статическая/детерминированная проверка сценарной модели, НЕ браузерное тестирование уже написанной игры. Движок, ветки с полным состоянием и мобильный экран ещё предстоит реализовать.

## Что НЕ утверждено
- Название окончательно, трактовка «нулевой эвакуации» и роль Вейла в большой арке ещё редакторские решения.
- Точное число и содержание всех фоновых реплик может измениться после проверки логики сцен.
- Звук, иллюстрации, новые портреты, анимации **не создаём без предварительного согласования и отдельного утверждения пользователя**.
- Ни одна сцена, награда или новая строка сохранения №002 пока не встроена в игру.
