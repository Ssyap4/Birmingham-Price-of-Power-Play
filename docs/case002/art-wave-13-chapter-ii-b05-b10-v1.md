## Материалы и решение по кандидатам

- **B05**: **установлена и зарегистрирована (1/6 текущей волны)**. Отдельный широкий кадр шлюза и специально скомпонованная вертикальная версия загружены в GitHub как настоящие WebP; Git blob SHA сверены с локальными оригиналами. Мобильный кадр композиционно оставляет видимыми рабочего, его жест и набережную со следами. Подписи сцены отсутствуют на изображении.

## Контракт передачи следующей партии

Для каждого из B05–B10 нужны **два независимых игровых WebP**: широкий 1200×675 и телефонный 720×900. Не растягивать широкий кадр на телефон; важные действия/улики оставлять вне нижних 25% экрана под HTML-диалог. В самих картинках не должно быть титров, подписи сцены, фактических выдумок или текста интерфейса. Постоянные NPC всегда сверяются с десятью уже утверждёнными портретами.

Фактическое принятие требует сохранения двух бинарных файлов, визуального просмотра и технической проверки размеров, RIFF WebP, SHA-256, сценической уникальности, соответствия сюжету, телефона 360/390/430 px. Только после этого вместе с файлами дописывается `src/case002/approved-art-v1.js`; затем запускаются адресные `art-audit` / scene-cast / approved-art и быстрый Chromium. При графической волне **не** запускать 400 маршрутов без изменений движка или контракта.

Текущий результат волны 13: **B05 = 2/2 WebP**, B06–B10 = 0/10 игровых WebP. Первой волны это не меняет: там остаются 16/16; суммарно зарегистрировано **17 сюжетных сцен и 10 NPC-портретов**. CI должен подтвердить коммит отдельно; до этого не объявлять автоматические проверки успешными.
