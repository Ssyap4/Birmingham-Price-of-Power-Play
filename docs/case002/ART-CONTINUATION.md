## Каноническая система: один кадр — один сюжетный момент (v2)
1. Прочитать точную сцену в case002-screenplay-acts-1-3-v2.md, её раскадровку и art-wave-16-chapter-iii-c01-c05-v1.md. Следовать art-generator-protocol-v1.md.
2. Для сцены составить одну **структурированную карточку**: тип кадра (атмосфера / диалог / действие / эмоция / улика / переход / последствия), его сюжетный момент и положение камеры, 2–4 обязательных визуальных признака, фон, свет, допустимые NPC и границы знаний игрока.
3. В сам генератор отправлять **только RENDER** одной сцены, никогда контрольный REVIEW, негативные списки и статусные слова. Никаких разговоров об алгоритме, предыдущих сценах и планах. Не перечислять соседние эпизоды и не создавать многосценные коллажи/инфографику.
4. Компилятор: node docs/case002/art-wave-prompt-builder-v1.js --cards docs/case002/art-wave-16-shotcards-v1.json --id C04. Для подготовки партии: --all --out-dir DIR создаёт **отдельные текстовые промпты**, не один общий запрос к генератору.
5. Проверка качества самим художественным руководителем: смысл выбранного типа кадра читается, сюжет не раскрывается заранее, портрет постоянного NPC соответствует эталону, нет определённого выбираемого героя (Джек, Финн, Элеонора, Виктор, Сэмюэл). После двух неверных результатов остановить прежний запрос и заменить постановку.
6. Новые игровые WebP — **720×900 (4:5), mobileOnly:true**. Без фиктивного desktop-мастера. Подготовить python docs/case002/prepare-art-wave-v1.py --input-dir DIR --output-dir DIR --ids C01 C02 C03 C04 C05; физическое декодирование, SHA-256, размеры, байты и dHash. Подготовка — не утверждение.
7. После визуальной приёмки всей партии — атомарно загрузить реальные файлы в assets/case002/scenes/ и записи в src/case002/approved-art-v1.js. Затем адресные art-тесты и быстрый Chromium на ширинах 360/390/430 CSS px. **400 seeded-маршрутов не нужны только из-за картинок**.
