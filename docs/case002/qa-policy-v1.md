# Дело №002 — политика адресных проверок v1

**Цель:** не запускать 400 случайных прохождений и два браузера после каждого небольшого косметического изменения, при этом не ослаблять проверку необратимых решений и сложных концовок.

## Как выбирается проверка

| Изменение | Автоматическая реакция |
|---|---|
| `README`, текстовые заметки по плану | Проверка определения изменений; без 400 маршрутов и установки браузера |
| `style.css`, небольшое оформление | Проверка JavaScript, локальный тест диалоговой типографики, быстрый Chromium с реальными мобильными размерами |
| Мобильный `app.js`, `index.html`, визуальные компоненты | Адресные UI-тесты и быстрый Chromium; без 400 маршрутов |
| `evidence-icons-v1.js`, `deduction-board-v1.js` | Тесты 26 улик и шести дедукций, плюс быстрая мобильная проверка; без 400 маршрутов |
| Портретные реестры, художественная раскадровка, выбор кадров | Тесты кадров, состава персонажей, допуска изображений; быстрая мобильная проверка, без тяжёлого сюжетного прогона |
| Добавление/изменение **реальных WebP** в `assets/case002/scenes/` или `portraits/` | **`art` + быстрый мобильный Chromium**; не запускать 400 маршрутов только из-за графического файла. Неизвестные расширения по-прежнему ведут к полному безопасному прогону |
| `story-variants-v4.js` и сценарные главы | Проверки 35 сюжетных финалов и соответствия текстов, проверка офлайн-пакета, быстрый мобильный браузер |
| `journal-v1.js`, уведомления о последствиях | Их адресные тесты и краткий мобильный прогон |
| `engine-v3.js`, граф, контракт, реальные условия переходов или сохранений | Полные сценарные проверки, включая 400 seeded-прохождений, все семь финалов, восстановление сохранений; полный Chromium + WebKit |
| Неизвестный тип файла, непонятная база сравнения или новая ветка | **Безопасный отказ от ускорения:** полный тестовый набор |
| Крупный релиз и вручную запущенный `workflow_dispatch` | Полная проверка. Вручную запустить **оба** workflow: сценарный и мобильный |

## Как это устроено технически

- [Определитель областей](../../tools/case002/ci-scope-v1.js) сравнивает `github.event.before` с текущим `github.sha`; учитывает все файлы пуша, не только последний коммит. Использует полную историю git (`fetch-depth: 0`).
- [Собственный тест политики](../../tests/case002/ci-scope-v1.test.js) проверяет типы правок и **fail-closed** для незнакомых файлов. Он запускается после каждого изменения, подпадающего под сценарный workflow.
- [Сценарный workflow](../../.github/workflows/case002-story-qa.yml) по области изменения включает только соответствующие узкие группы. Проверка синтаксиса JavaScript остаётся дешёвой и общей.
- [Мобильный workflow](../../.github/workflows/case002-mobile-smoke.yml) при мелких изменениях устанавливает только Chromium и запускает `python tests/case002/mobile_browser_smoke.py --quick`. Проверки открытия, сцены P02, доказательств, сохранения и ширин 360/390/430 остаются.
- При серьёзном изменении или ручном запуске ставятся Chromium **и** WebKit, а `mobile_browser_smoke.py` выполняет полный маршрут до F09 и проверку меню исходов.
- `concurrency` отменяет устаревшие проверки той же ветки, чтобы после серии мелких пушей запускалась только актуальная проверка. В GitHub старые запуски могут иметь статус `cancelled` — сам по себе он не означает падение последнего коммита.
- Любая нетипичная правка, вызывающая сомнение в классификации, должна сопровождаться ручным полным запуском. Быстрый тест не заявляется как эквивалент полной приёмки.

## Следующее небольшое улучшение v5.0

[Рендерер реплик](../../src/case002/scene-prose-v1.js) меняет **только представление** текста: строка, начинающаяся с длинного тире, получает оформление прямой речи, но не автоматически назначенного говорящего. Порядок и символы реплик сохраняются. Тексты вставляются только через текстовые DOM-узлы, без `innerHTML`. [Локальный тест](../../tests/case002/scene-prose-v1.test.js) проверяет сохранность слов, сценарные абзацы и отсутствие HTML-инъекций; быстрый мобильный тест проверяет реальные реплики Мэйбл в P02.

Это решение **не вводит новые механики, награды или сюжетные ветки**. Дело №001 и стабильный `main` не трогаем. Качественная игра по-прежнему требует полного прохождения и проверки на настоящем iPhone перед публичным выпуском.
