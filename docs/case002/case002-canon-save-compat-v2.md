# Переход Дело №001 → Дело №002: безопасный канон и сохранения v2
**Статус: спецификация, НЕ включено в основную игру.** Разработана на основании текущих файлов main: campaign-hub-v1.js, heroes-v1.js, case-v14.js. Цель — исключить ложное «воскрешение» героя, перетирание истории, повтор награды и фантомные знакомства.

## 1. Источники данных в существующей игре
- Данные №001 по герою: `birmingham_case_smol_heath_v1_<heroId>`. `node` может быть `endingRescue`, `endingEvidence`, `endingDeal`, `endingTruth`, `endingPower`, `endingDeath`.
- История попыток: `birmingham_campaign_records_v1` (массив: `key`, `caseId`, `heroId`, `started`, `finished`, `ending`, `items`, `deductions`, `visited`, `health`, `cause`). Не считать этот массив полным, если пользователь ещё не заходил в архив после завершения дела.
- Уникальные награды: `birmingham_campaign_unique_rewards_v1` (ключ `001:<heroId>:<endingId>`). Новые `002:<heroId>:<endingId>` не должны заменять, очищать или удваивать существующие ключи.
- Выбранный герой: `birmingham_hero_selection_v1`. Последний выбранный герой **не является** каноном сюжета.
- Словарь персонажей: `jack`, `finn`, `eleanor`, `victor`, `samuel`.

## 2. Отдельное явное решение
Перед первой попыткой №002 пользователь видит компактный мобильный экран «Откуда начинается ваша история?», после выбора героя:
1) «Продолжить одну из моих историй №001» — список завершённых записей (с датой, героем, итогом) для осознанного выбора;
2) «Начать самостоятельное расследование» — нейтральный вариант, если в №001 нет подходящей истории или пользователь хочет новую точку входа.
Записать `priorCase001RecordKey` **как snapshot выбора**, `priorCase001EndingId` и `priorCase001HeroId` в новую попытку; не брать на каждом экране «последний» исход.
Если выбрана каноническая смерть того же героя, не начинать №002 им же. Предложить другого живого героя либо явный выбор иной завершённой линии №001. Не изменять коллекцию старых попыток.
Привязка к №001 учитывает только те воспоминания, которые герой мог пережить; другой герой может знать последствия из газеты, но не произносит реплики «я сказал Риду...» без личного участия.

## 3. Обработка прошлого исхода — без влияния на базовую проходимость
| №001 endingId | Допустимое последствие | Недопустимое предположение |
|---|---|---|
| endingRescue | Эвелин и Артур живы, могли дать осторожный совет | «У нас есть вторая книга и полные документы» |
| endingEvidence | Артур выжил, ранен; у героя могут быть копии контрактов | «Артур здоров, может участвовать в погоне» |
| endingDeal | Крейн получил/уничтожил большую часть документов; осторожный намёк на сделки | «Вся сеть разоблачена» |
| endingTruth | огласка №001; Рид-полицейский пропал, Крейн скрывается | «Сержант Рид ведёт новый допрос в участке» |
| endingPower | компромат скрыт; дополнительный повод для давления | «Документы уже доступны каждому журналисту» |
| endingDeath | этот герой погиб в выбранной версии №001 | «Он просто снова идёт работать» |
| null | нейтральная история, новые игроки узнают всё необходимое в №002 | фантомные знакомые, уникальные ключи «из прошлого» |

## 4. Идемпотентное сохранение
Разделить три операции:
- `saveDraft(caseId,hero,attemptId)` — временный прогресс одной попытки; не выдаёт достижений.
- `completeAttempt` — одна транзакция по `attemptId` записывает завершённую историю, snapshot witness/evidence/decisions и каноническую привязку; повторный вызов не дублирует строку.
- `grantUnique` — только после успешного complete, ключ `002:<heroId>:<endingId>` добавляется если отсутствует. Сначала локальная версия, при сетевом релизе — серверное уникальное ограничение.
**Никакая операция в №002 не изменяет существующий `birmingham_case_smol_heath_v1_*`**. Миграция истории делать явно, с сохранением обратной совместимости. Перемена героев не может переписать выбранную сюжетную биографию при возобновлении попытки.

## 5. Когда сценарий зависит от канона
- При открытии P02 — изменяется только короткое вступление, не набор обязательных доказательств.
- В промежуточных разговорах с подрядчиками — дополнительная реакция, только если соответствующий герой реально встречался с Крейном/Ридом и выбран канонический исход.
- При выборе исхода №002 — последствия №001 могут изменить отношение города, но не должны тайно отключать `trainEscape` либо лишать игрока базовых доказательств.
- Сержант Рид (№001) и **Сэмюэл Рид, механик** — два разных человека. Не сливать их записи, портреты, голоса или биографии.

## 6. Тесты обязательны до интеграции
- 6 исходов №001 × 5 героев × 7 исходов №002: минимум проверка правил допустимости и совместимости (210 условных сочетаний), плюс нейтральный старт.
- Особое правило: same hero + endingDeath — запрет; другой герой + endingDeath прошлого персонажа — допустим с соответствующим контекстом (не автоматическая смена канона).
- Повтор 001 и 002 не меняет выбранный сюжетный snapshot, пока пользователь не подтвердит изменение.
- Сохранить 30 старых уникальных комбинаций Дела №001; идентификаторы 002 образуют новые комбинации, не конфликтуют.
- Не менять состояние, если сохранение не удалось; на мобильных ограничениях localStorage обработать ошибку и предложить экспорт/повтор.
