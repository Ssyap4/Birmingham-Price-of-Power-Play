# V5 — Полировка криминального режима и безопасное объединение кампании

Дата: 16 ноября 2026. Рабочая ветка: `feat/criminal-operations-polish-v3`.

## Уже реализовано в этой ветке

В **общем HTML** (`index.html`) уже есть вход `#criminalEntry` в новый режим, а сценарии `src/criminal/missions/cr01.js` ... `cr05.js` работают через отдельные `src/criminal/engine.js` и `archive.js`. Включены также Детективные дела №001 и №002. Следовательно, нам нужно **не переписывать все три режима заново**, а завершить полировку, проверить общий пакет и после согласия автора перенести только проверенные изменения из ветки.

Текущий рабочий пакет: карта теперь читает отдельно валидированные локальные слоты пяти поручений (`empty`, `active`, `finished`, `corrupt`, `unavailable`), показывает состояние в списке и у пинов, даёт продолжение или просмотр результата вместо одинаковой подписи. Хроника фильтруется по CR01–CR05 и отображает по 10 завершённых попыток за страницу; никакие исходы/награды не удаляются, в хранилище ничего не переписывается фильтром. Код: `src/criminal/app.js`, `criminal-operations-v2.css`; регрессии в `tests/criminal/mobile_browser.py`.

## Обязательные условия объединения

1. **Профиль:** режим «Криминальные дела» должен выглядеть частью одной игры, но до серверной версии не следует заявлять единый аккаунт или синхронизацию между браузерами. Локальные знаки криминальных дел подтверждаются только его проверяемой историей; архив Детективного дела №001 опирается на `birmingham_campaign_records_v1` и другие собственные ключи. Никакого молчаливого копирования между этими структурами.
2. **Навигация:** главное меню предлагает детективные дела и криминальные поручения как три направления. Внутри криминального режима работают Карта, Хроника, Меню; выход при неподтверждённой записи не теряет прогресс без предупреждения. Для iPhone на экранах 320–430 px нет перекрывающих элементов.
3. **Прогресс:** сохранение CR01–CR05 имеет отдельный префикс `birmingham_criminal_v2_`. Финалы, боевые риски и награды нельзя определять по видимым CSS или изменяемым DOM; источники истины — подписанный историей результат `Engine.validateState` и `Archive.recover`.
4. **Награды:** уникальная комбинация «поручение × герой × финал» награждается однократно. Повтор не вызывает ложное всплывающее уведомление. Общий экран наград позже может показывать *проверенный read-only снимок* из разных режимов, не меняя старых ключей.
5. **Художка:** все 40 установленных WebP криминальной кампании должны декодироваться на устройстве и сохранять 720×900. Новые авторские иллюстрации добавляются **по одной на пользовательское сообщение и на одну сцену** с визуальной приёмкой; не использовать кандидат без загрузки байтов и manifest SHA. По завершении криминальной арт-полировки уравновесить обрамление 001/002 и нового режима, не меняя канонические сюжеты.
6. **Автотесты:** нужны адресные Node-прогоны графа/концовок, настоящая мобильная матрица Chromium+WebKit по затронутым экранам, проверка старых слотов без побайтных изменений и один экспорт объединённой офлайн-сборки. Избыточный повтор всех старых 202 сценариев после изолированной CSS-поправки не требуется.
7. **Релиз:** `main` и старая `preview/unified-campaign-safari` остаются нетронутыми до независимой приёмки, включая проверку на реальном iPhone. Текущая `https://birmingham-criminal-v3-safari.vercel.app/` — отдельный Vercel-проект с кодом/ассетами, закреплёнными за более ранним проверенным commit SHA; новые изменения GitHub **не попадают туда автоматически**.
