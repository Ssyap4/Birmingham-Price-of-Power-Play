# ADR-0006 — 15+1: учёт ответов для переноса чата, не график релизов

**Дата:** 2026-11-15. **Статус:** accepted (постоянное правило автора).  
**Область:** вся разработка «Бирмингем: Цена власти»; работа в GitHub и передача контекста между беседами.  
**Дополняет:** [ADR-0005](0005-risk-proportionate-qa-and-milestone-delivery.md). Не меняет порядок проверки и публикации бета-сборок.

## Контекст

Длинная разработка не помещается в одну переписку. Автор ввёл правило «15+1», чтобы поддерживать точность памяти при переходе в следующий чат. Использование номеров этапов как счётчика готовности игры, требования выпустить сборку к определённому номеру или причины ускорить публикацию — **ошибка**.

## Постоянное решение

1. **15+1 считает ответы ассистента внутри текущего чата, а не объём готовности проекта.** Первые пятнадцать ответов — реальные, по возможности крупные и комплексные этапы разработки по текущим приоритетам и правилам качества.
2. **Ровно на 16-м ответе** не начинать новую разработку, не генерировать иллюстрации и не инициировать новую публикацию: создать исчерпывающий, готовый для копирования промпт-передачу в следующий чат.
3. Промпт включает: точную игру/дело и рабочую ветку; проверенный актуальный HEAD; завершённый этап и незавершённые работы; результаты и ссылки **только фактически выполненных** CI/QA; текущие файлы и архитектуру; 15+1; ADR-0005; художественный протокол, запреты на main/Дело №001/сохранения; следующий конкретный шаг; условия Safari-приёмки. Не переносить догадки как факты.
4. Следующий чат начинает отсчёт заново **с 1/15**, возобновляя работу с проверенного GitHub HEAD, без повторного придумывания проекта и без необходимости просить автора пересказать историю.
5. **Номер ответа не является дедлайном, планом релиза, критерием готовности или обязанностью показать сборку.** Ни ускорять, ни задерживать Safari-показ из-за границы чата. Версия предоставляется для приёмки лишь после реальной готовности, соразмерных релизных проверок и проверенной HTTPS-публикации, **в любом чате и на любом номере**.
6. Крупные рабочие пакеты, самостоятельная ревизия и адресный QA из ADR-0005 действуют независимо от 15+1. Мелкие правки не требуют выдавать ZIP/HTML для тестирования автору.
7. При новом чате читать этот ADR и ADR-0005, сверять рабочую ветку/HEAD и учитывать самый свежий промпт-передачу. Если пользователь уточнит правило, отразить изменение отдельно, а не интерпретировать цифры заново.

## Последствия и доказательства

- Правило сохраняется в публичном репозитории без секретов и личных данных; его можно восстановить после смены чата.
- Система передач не вмешивается в сценарий, награды, механику или сохранения.
- Реальные Safari-милстоуны по-прежнему определяются [release gate](../case002/SAFARI-BETA-RELEASE-GATE.md) и ADR-0005, а не счётчиком ответов.
